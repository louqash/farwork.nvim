*farwork.txt*  Local editing with remote clangd and builds

SETUP                                             *farwork-setup*
Requires Neovim 0.11+, Python 3, Git, SSH and rsync 3+ locally.
Remote: Python 3.9+, Git and rsync. C/C++ mode also needs clangd and a
compilation database. Set lsp=false in a project profile for sync/build/checks
without remote language features; choose build_command for that project.
>
    require('farwork').setup({ keymaps = false })
<
Setup registers commands; connections are opt-in. keymaps=true enables
<leader>rs/rb/rd for start/build/diff and <leader>us/ui for upload/status.
Use :checkhealth farwork to check local prerequisites.

OPTIONS                                           *farwork-options*
keymaps          Boolean; false by default. Install optional leader mappings.
notify_uploads   Boolean; false by default. Show successful per-file uploads.
projects         Map local roots to host/remote/build/environment/lsp profiles.
git.auto_fast_forward  Boolean; false. Advance matching remote Git history.
check_command    Argument list; defaults to pre-commit run --hook-stage pre-commit.
check_args       "pre-commit" appends file flags; "none" leaves argv unchanged.
operation_timeout  Positive seconds; 120 by default, for setup/Git/recovery.
check_timeout    Positive seconds; 600 by default, for remote checks.
rsync            Local executable name/path; defaults to "rsync".
clangd_args      Remote clangd flags; default background-index and clang-tidy.
build_command    Function(project) returning argv; default cmake --build.
upload_exclude   Function(relative_path) returning true to exclude extra uploads.
state_dir        Saved project settings directory; default stdpath('state').
cache_dir        Header cache parent directory; default stdpath('cache').

Build arguments are quoted automatically. Exclusions are additive and only
affect uploads. SSH identity/proxy settings come from ~/.ssh/config. Remote
environment activation is saved per project through :FarworkStart!.

COMMANDS                                          *farwork-commands*
:FarworkStart [dest]   Connect from a project/subdirectory; optional host:/path.
:FarworkStart!         Prompt for destination, environment and build directory.
:FarworkProjects       Connect to a saved/configured project, then :cd its root.
:FarworkTrust          Open .farwork.json for review and explicit trust approval.
:FarworkTrust!         Remove its saved trust decision; active sessions continue.
:FarworkSync           Retry uploads and sync saved files without restarting LSP.
:FarworkStatus         Show project and language-server status.
:FarworkRefresh        Restart remote clangd once uploads are idle.
:FarworkBuild [args]   Sync saved files, then build; append safely quoted args.
:FarworkDiff[!]        Show remote unstaged [staged] diff. q closes the split.
:FarworkUploadStart [dest]   Upload files without starting remote clangd.
:FarworkUploadStatus        Show current transfer/queue state (after uploads start).
:FarworkUploadWait          Wait up to 30 seconds for uploads.
:FarworkDoctor        Diagnose upload/Git errors and review a guarded repair.
:FarworkUploadRetry         Retry a failed queue without discarding saved files.
:FarworkUploadStop          Cancel the active transfer/guard and discard its queue.
:FarworkCheckStop     Cancel a running check without applying returned fixes.

:FarworkProjects works from any directory. It switches to the selected local
root only after setup and the initial upload succeed. Cancellation or failure
keeps the current directory; a successful upload retry completes the switch.
Existing buffers stay open. Nothing is cloned into the directory you started
from. :FarworkStart and auto-connect do not change directories. The directory
change uses :cd (global, not :lcd or :tcd).

The picker also lists the current directory/current buffer's .farwork.json
project and remembers file-project paths after successful connection. Settings
are never copied: every connection rereads the file and verifies trust, even
from another directory. Changed contents require renewed approval. Listing a
project does not trust or execute it. Existing connections keep their settings.
Removing the marker hides a remembered file-only project from the picker.

Commands use Farwork prefixes; former Remote/Upload names have no aliases.
Update custom mappings to the commands above.

BEHAVIOR                                          *farwork-behavior*
Clangd connects independently of the initial upload and stays available during
Git conflicts/history mismatches. Open-buffer changes reach clangd over LSP;
uploads remain guarded. Remote headers/other files may be stale until sync
resumes. :FarworkRefresh works while uploads are blocked. Finish the Git
operation, reconcile histories with :FarworkDoctor if needed, then use
:FarworkUploadRetry (or :FarworkStart if uploads were stopped). Builds/checks
still require completed initial sync.

Local files overwrite corresponding remote files. Git metadata, virtual
environments and build outputs are excluded. Deletions are not propagated.
FarworkStart checks that Git HEAD and branch match; it does not reconcile
history by default or run remote stash/reset/checkout. Interrupted first-time
downloads resume on reconnect without replacing existing local files. FarworkUploadStart has no Git guard.
Queues live in memory. Save buffers before quitting. Use one uploading editor
per remote project. C++ language-server requests require a live connection.

Saved state uses remote-projects.json, upload-projects.json and
project-roots.json (file-project paths only, no settings or trust) under
stdpath('state'), retaining settings from the original dotfiles integration.

API                                               *farwork-api*
require('farwork').start({root=..., destination=..., build=...,
                                  environment=..., reset=false})
    Connect using explicit options or saved/profile values. start(true) remains
    an alias for interactive reconfiguration. With no root, resolve from cwd.

require('farwork').status()
    Return root/host/remote/build, connecting, ready, lsp_connected, and upload
    state (enabled, busy, queued, error, message). No notifications or network.

require('farwork').project_root(path)
    Deepest matching saved/configured/file root, then Git root, then directory.

require('farwork').owns_buffer(bufnr)
    True for local files and cached headers owned by the active remote project.

Profile example: >
    require('farwork').setup({
      projects = {
        ['~/src/app'] = {
          host = 'build-host', remote = '/home/dev/app',
          build = '/home/dev/app/build',
          environment = 'source /home/dev/app/.venv/bin/activate',
        },
      },
    })
<
Profiles override saved values; no repository-local Lua is executed.

See README.md for installation, local clangd integration and detailed limits.



LSP INTEGRATION                                    *farwork-lsp*
Use require('farwork').local_clangd_root as vim.lsp.config.clangd.root_dir
so local clangd does not start in known remote projects.

In clangd mode, Farwork detaches local clangd from active project buffers. Keep your usual
LspAttach callback; no Farwork-specific early return is needed. The remote
client is named "remote_clangd".

With keymaps=true, Farwork installs buffer-local <leader>ch for local and
remote clangd. No source/header request code is needed in your configuration.
For a custom mapping, call require('farwork').switch_source_header(bufnr).
The optional bufnr defaults to the current buffer. Remote clangd is preferred;
local clangd is used when Farwork does not own the buffer's language server.


PROJECT FILES AND AUTO-CONNECT                     *farwork-project-file*

Place .farwork.json at the local project root:
>
  {
    "host": "build-host",
    "remote": "/home/dev/my-app",
    "build": "/home/dev/my-app/build",
    "environment": "source /home/dev/my-app/.venv/bin/activate"
  }
<
Host and remote are required. Build, environment and lsp are optional.
lsp defaults to "clangd"; false skips compiler/database discovery and keeps
local language servers available. Choose an appropriate build_command. Paths are
absolute remote paths. Neovim asks to trust the file before using it, including
when contents change. Denied/invalid files stop connection setup.

TRUST                                             *:FarworkTrust*
                                                  *farwork-trust*
:FarworkTrust finds .farwork.json from the current file, falling back to cwd.
It opens a read-only split and offers Cancel (default) or Trust this config.
Approval trusts the displayed, unmodified buffer through vim.secure.trust.
Changed or renamed buffers require a new review. No connection starts from
this command; run :FarworkStart afterwards. Previously denied files can be
reviewed and approved this way too.

:FarworkTrust! removes the saved decision through Neovim's trust database.
It does not stop an active connection/upload. Future connections must review
the config again. Content changes invalidate approval automatically.
The built-in :trust command remains available for managing Neovim trust.

Enable automatic connections once in your Neovim config:
>
  require("farwork").setup({ auto_connect = true })
<
Default: false. Applies to saved projects, Lua profiles and project files.
Discovery walks upward from the current file (cwd for an empty buffer), stopping
at a marker or the nearest Git root, inclusive. The deepest matching marker or
saved/Lua root wins. Lua fields override JSON; JSON replaces saved settings.
No arbitrary repository connects. Failed/cancelled attempts require :FarworkStart
to retry. An active project is never automatically replaced by another one.

The environment command applies to discovery, clangd, builds, checks, Git
synchronization and recovery helpers.
Local Git hooks are NOT forwarded. Use :FarworkCheck for remote staged checks.

:FarworkCheck                                     *:FarworkCheck*
    Open an output split immediately, streaming progress while hooks run.
    Run pre-commit on staged added/modified files in an isolated remote copy of
    the local index, using the project environment. ! checks all index files.
    Returned fixes apply automatically only if staging and affected local files
    still match the snapshot and their buffers are unmodified. Buffers reload;
    upload runs through the Git guard. Review, stage fixes and rerun the check.
    Conflicts and deletions require review; results remain under cache/checks/.
    Does not install a Git hook or change either repository's index. Requires
    Python 3.9+. Submodules/external symlinks are not supported; hooks needing
    working-checkout build artifacts may fail. See README for full limitations.

GIT FAST-FORWARD                                 *farwork-git-fast-forward*
setup({ git = { auto_fast_forward = true } }) opts into verified remote metadata fast-forward.
Save and finish uploads before committing locally. The next upload can advance
remote HEAD/index if branches match, history is a fast-forward, the remote index
is unstaged, and remote tracked files exactly match the local commit. The old
commit is retained in refs/nvim/backups/commit-*. No working files are changed.
Rebases, branch switches, deleted/renamed paths, staged remote work, and mismatched
contents still pause uploads. Default: false. This does not create local commits.

RECOVERY                                         *farwork-recovery*
                                                 *:FarworkDoctor*
Run :FarworkDoctor when an upload error tells you Git histories differ. It holds
uploads (new saves remain queued), opens a report with both commits and affected
paths, and offers a repair only when the proposed writes are verifiable. Cancel
is the default. No repair runs until you select it. The plan is checked again
before applying it; changes during review stop recovery.

COPY: remote file matches its old committed version, so the local commit can
replace it. KEEP: remote file already matches the local commit. REVIEW: preserve
and resolve this file manually. A repair may replace remote history after a
rebase; the local COMMIT is authoritative. Backups retain the remote old commit
and target under refs/nvim/backups/recovery-*/head and /target.

Supported: modified regular tracked files whose contents are either old or
already desired, on matching branch names with no local uncommitted work or
remote staged changes. Protected venv/build files and untracked files are left
alone. No stash, clean, reset or checkout commands are used.

Blocked: finish active Git operations; preserve remote staged/conflicting work;
review missing remote commits (fetch command shown); reconcile added/deleted,
renamed, symlinked or protected paths manually. The report names the reason and
next step. See README's recovery table for details. Never blindly delete locks
or clean/stash a remote venv.

On success the existing queue resumes. If uploading was stopped, :FarworkStart
reconnects. On cancellation/failure the queue stays paused. An interrupted
repair may have updated some verified files; its error reports the backup.
Rerun :FarworkDoctor to inspect the new state. Do not operate another Git process
or uploading editor on that checkout while recovery runs.

Daily: save, :FarworkUploadWait successfully, commit locally. Rebase: finish uploads,
:FarworkUploadStop, finish the rebase locally, then :FarworkDoctor. A push alone does not
update the remote working checkout.
